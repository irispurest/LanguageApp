# AGENTS.md

## Проект
Офлайн-приложение для изучения языков, первый — японский. Идея: не узкий тренажёр, а универсальная среда (грамматика с тестами, интервальные повторения, словарь, тексты) с короткими игровыми сессиями. Стек: React Native + Expo + TypeScript. Бэкенд для базового функционала не нужен; если появится позже — C#/.NET, не Node.

## Принятые решения
- Одно приложение: универсальное ядро + языковые адаптеры + course packs. Японский — первый language pack. Конструктор курсов и скачивание паков — позже.
- IA: 5 табов — Главная, Курс, Словарь, Грамматика, Тексты. Повторение — stack-режим, не таб. Главная = следующий урок/повторение/статистика/настройки; Курс = чистый список уровней/разделов/уроков.
- Один курс «Японский» с уровнями N5/N4/N3; уровень → разделы → упорядоченные уроки. Типы уроков: grammar, vocabulary, text; listening позже. Review — не тип урока, а режим/политика.
- Справочники: один список с фильтрами «Все/Пройдено», без двух копий. Словарь по умолчанию личный; сортировка по добавлению/прогрессу/алфавиту, **без группировки по уровню**. Поиск по глобальному JMdict, личные результаты помечены. Прогресс слова — из FSRS, статусы «Новое/Учится/Закрепляется/Уверенно», без сырого процента.
- Повторение: после каждого урока, до 10 слов за сессию (лимит настраиваемый). Глобальная кнопка «Повторить» на Главной. Отдельного урока/таба повторения нет.
- Общий раздел справочников называем «Библиотека».
- Авторство уроков — JSON + CLI, без in-app редактора. Zod — для схем контента и `z.infer`.
- Контент: `content/ja/manifest.json` (уровни → разделы → уроки), отдельные каталоги `lessons/`, `grammar/`, `texts/`; уроки ссылаются на общий пул. `content/ja/index.ts` генерируется, не редактировать вручную.
- Цвета: `accent #B6465F` (розово-красный), `accentSoft #F7DAD4` (персиковый), `accentInk #8E2F45` для текста на мягком фоне. Менять только через `theme.ts`.
- Навигация: JavaScript tabs из Expo Router; root Stack для «О приложении»/повторения. Route-файлы тонкие, экраны — в `src/features/`.
- Первый этап — только Android-телефон через Expo Go. iOS вне scope, пока пользователь явно не попросит; iOS-специфичную работу не добавлять.
- Первый вертикальный срез — грамматика + тесты, а не кана/SRS. Словарь, SRS и тексты — следующие этапы, но схема данных и стабильные ID проектируются под них уже сейчас.
- Словарь — офлайн, JMdict-rus из `jmdict-simplified`; на старте common-only. Лицензия CC BY-SA 4.0: атрибуция в приложении, share-alike для производной БД, процедура обновления.
- Тексты токенизируются на этапе сборки; на телефоне никакого runtime-токенизатора. Токены хранят `surface`, `lemma`, `reading`, `entryIds`.
- UI и переводы — русский first; строки в `src/i18n/`, не в JSX.
- Expo SDK — последний стабильный на момент скаффолда; не canary/next.

## Первый срез: грамматика + тесты
Цель — проверить полный офлайн-цикл на одном языке и одном типе контента, не строя весь комбайн.
- Контент: 1–2 грамматических урока из знакомых пользователю N5-тем (уровень N5+, новые темы не нужны) с объяснением, примерами, чтением и переводом. Первый урок — `は` и `が` (выбрано пользователем).
- Упражнения: выбор варианта, пропуск из банка слов, упорядочивание частей предложения. Без free-text ввода на японском.
- Прогресс: SQLite; сохранять ответы, завершение урока и ошибки; всё работает без сети.
- Проверка: unit-тесты на проверку ответов и валидацию course pack; ручной прогон на Android-телефоне.
- Не входит: словарь, SRS, тексты, аудио, рукописный ввод кандзи, конструктор курсов. Схему БД и ID не проектировать так, чтобы они блокировали эти функции.

## Ограничения продукта
- Offline-first: основные сценарии работают без сети. Нет обязательного логина, облака, аналитики и сетевых запросов в core-путях. Не добавлять backend/auth/sync без явного запроса.
- Лёгкость: короткие сессии, минимум тяжёлых зависимостей, ассетов и экранов. Не превращать приложение в комбайн.
- Японская специфика (кана, кандзи, фуригана, токенизация) живёт в языковом адаптере, а не в ядре.
- Пользователь параллельно учит React Native: объясняй по-русски, что и зачем делается, предлагай простой и явный код, избегай «магии» и преждевременных абстракций.
- Перед крупными изменениями — короткий план и подтверждение. Новую зависимость добавлять только с обоснованием.

## Обучение и объяснения
- Пользователь знает основы TypeScript, основной язык — C#. Объясняй TS через аналогии с C#: структурная типизация vs номинальная, union/discriminated unions vs иерархии классов, generics, strict null checks vs nullable reference types, `type` vs `interface`, utility types, inference, модули.
- Объясняй не только «что», но и «почему»: какой паттерн применяется (repository, strategy/registry, adapter, composition), какие есть альтернативы и trade-offs.
- Перед выбором архитектуры предлагай 1–2 варианта и рекомендацию; не добавляй абстракцию без второго реального use case.
- По React Native объясняй: компоненты/экраны, JSX, props/state, хуки, StyleSheet/Flexbox, Pressable/Button, навигацию (Expo Router), анимации (Animated/Reanimated), списки и ввод.
- Один шаг за запрос. Не реализовывать будущие этапы без подтверждения. После шага — краткое объяснение изменений и способ проверки.
- Код должен быть понятным для изменения: явные имена, маленькие модули, без «магии».

## Дизайн-гейт
- Перед изменением экранов, навигации, информационной архитектуры, формата контента или схемы данных: сначала предложить 1–2 варианта с trade-offs и получить явное подтверждение пользователя.
- Не добавлять экраны, разметку или фичи «на всякий случай» и не реализовывать будущие этапы.
- Текущий app shell — черновик. После согласования IA сначала обновить `docs/10-ux-ui.md`/`docs/15-implementation-plan.md`, затем код.
- Если пользователь описал видение — сначала разбор и вопросы, код только после согласования.

## Открытые решения
Не выбирать без пользователя. Актуальный список — `docs/14-open-questions.md`; ближайшие:
- хранение прогресса: отдельные таблицы по доменам или одна общая;

- common-only или полный словарь на старте, fallback при отсутствии русского глосса;

## Границы и паттерны
- `app/` — только маршруты Expo Router: `app/(tabs)/*`, `app/about.tsx`, `app/+not-found.tsx`. Не держать бизнес-логику в route-файлах.
- `src/features/` — экраны по фичам: home, course, dictionary, grammar, texts, review, about, not-found.
- `src/ui/` — тема и переиспользуемые компоненты (`Screen`, `Card`, `AppButton`, `Badge`, `EmptyState`, `SectionTitle`, `FilterChips`, `ContentRow`, `StatTile`).
- `src/i18n/ru.ts` — все русские строки; не писать литералы в JSX.
- `src/core/content/schemas.ts` — Zod-схемы и типы контента (создано). `src/core/` для упражнений/прогресса/SRS/БД — позже.
- `content/ja/` содержит sample-контент: `ja-n5-wa-ga` — placeholder, не финальный урок. Реальный контент — шаг 4.
- `src/languages/<code>/` — адаптеры языка; для японского — кана/кандзи/фуригана/токенизация (пока не создано).
- `content/ja/` — манифест, `lessons/`, `grammar/`, `texts/`; `index.ts` генерируется валидатором.
- `assets/dictionary/` — generated `dictionary-ja.db`, не редактировать вручную.
- `scripts/` — `validate-content.ts`, `content-new.ts`, тесты; `scripts/lib/validate-content.ts` — общая логика.
- Паттерны текущего UI: композиция маленьких компонентов; `variant`-union для кнопок/бейджей; `Record<Variant, Styles>` вместо switch; route → feature screen; стили из токенов темы.
- Импорты внутри `src/` — через `@/` (tsconfig paths).
- Две БД: `user.db` (read/write: прогресс, карточки, логи) и `dictionary-ja.db` (read-only asset). Никогда не писать в словарь.
- Контент читается из JSON, не импортируется в SQLite. Прогресс ссылается на стабильные ID.
- Без ORM в MVP: явные SQL-запросы и типизированные репозитории. Drizzle — только если появится доказанная необходимость.
- Время — epoch ms UTC; локальная граница дня — только для отображения.

## Команды
Проверено на текущем каркасе:
- `npm start` — запустить Expo Dev Server; открыть Expo Go и отсканировать QR (ПК и телефон в одной Wi-Fi).
- `npx expo start --clear` — то же с очисткой кэша; полезно после изменений `app.json`/роутера.
- `npx expo customize tsconfig.json` — перегенерировать typed routes после добавления/переименования маршрутов (иначе `router.push` ругается на старые пути).
- `npm run typecheck` — TypeScript strict без emit.
- `npx expo-doctor` — проверка зависимостей и конфигурации.
- `npx expo export --platform android` — smoke-test Android-бандла.
- `npm run content:validate` — проверить course pack, связи и токены; генерирует `content/ja/index.ts`.
- `npm run content:new -- --type grammar --level n5 --section n5-particles --title "..." --id ja-n5-my-lesson` — создать grammar-урок и вставить в раздел (`--dry-run` для проверки).
- `npm run test:content` — тесты схем/валидатора (Node test runner + tsx).
- `npm run android` — только при наличии Android SDK/эмулятора или adb; сейчас не использовать.
- `npm run ios`, `npm run web` — не нужны на этом этапе.

Lint и полноценный test suite появятся отдельными шагами. Не угадывать команды: сверяться с `package.json`.

## Подводные камни
- iOS сейчас не нужен. Не тратить время на iOS-симулятор, EAS/TestFlight и Apple Developer; это отдельное будущее решение.
- Expo Go годится для JS-only модулей; кастомные нативные модули требуют development build (JDK 17 + Android SDK). В MVP не добавлять нативные модули.
- Android-телефон + Expo Go: ПК и телефон в одной Wi-Fi; разрешить Node.js в Windows Firewall (порт 8081). Если сеть не видит — `npx expo start --tunnel` (нужен интернет).
- `npm run android` без Android SDK/adb не сработает; для Expo Go использовать `npm start` и QR-код.
- `npm audit` показывает 3 moderate через `minimatch` → `@expo/fingerprint` → `expo`. `npm audit fix --force` предлагает откатить Expo до 52 — не делать; ждать обновления Expo или проверять безопасный override.
- `react-dom` зафиксирован на `19.3.0` под React `19.3.0`. Expo Router может подтянуть `19.3.1` и вызвать ERESOLVE; не обновлять `react`/`react-dom` по отдельности.
- `expo-font` — прямая зависимость, требуется `@expo/vector-icons`; `expo-doctor` проверяет это. Не удалять.
- `content/ja/index.ts` генерируется `content:validate`; не редактировать вручную.
- `content:new` пока создаёт только `--type grammar`; схемы vocabulary/text есть, CLI для них позже.
- Токены текста используют UTF-16 индексы (`String.slice`); валидатор проверяет покрытие body. `entryIds` могут быть пустыми до сборки словаря.
- `scripts` используют Node API; `tsconfig` включает `types: ["node", "react"]`. Не убирать `node` из types.
- Не использовать глобальный `react-native-cli`; проект создаётся через `create-expo-app`.
- Metro не поддерживает динамический `require` с переменным путём: для course packs нужен сгенерированный `content/<code>/index.ts` со статическими импортами.
- `expo-sqlite` включает FTS5; в Expo Go доступен. Встроенный DevTools inspector открывается через Shift+M в Expo CLI — отдельный DB-клиент не обязателен.
- FTS5 trigram не ищет подстроки короче 3 символов: для коротких запросов нужен fallback на `LIKE`.
- JMdict/EDRDG: CC BY-SA 4.0, атрибуция в экране «Источники», share-alike для производной БД, процедура регулярного обновления. `jmdict-simplified` тоже атрибутировать.
- `ts-fsrs` v6 требует Node >= 24 (у нас есть); версию библиотеки фиксировать, алгоритм не переписывать.
- Японский ввод: free-text зависит от IME. Для первых упражнений использовать выбор, сопоставление и упорядочивание; фуригану рендерить кастомным компонентом.
- Большие словари, аудио и шрифты конфликтуют с «лёгкостью»: измерять размер, тяжёлые паки делать загружаемыми (но доступными офлайн после загрузки).
- SQLite: версионировать миграции; не терять прогресс пользователя при обновлениях. `withTransactionAsync` включает все запросы, выполняемые во время транзакции — держи область узкой.

## Рабочий процесс
- Сначала читай `AGENTS.md`, `docs/README.md`, `package.json` и конфиги; исполняемые источники важнее прозы.
- Пакетный менеджер по умолчанию — npm; не смешивать менеджеры и lock-файлы.
- Критичную логику (проверка ответов, SRS, миграции, поиск) покрывать unit-тестами; course packs валидировать схемой.
- Стабильные ID контента не переименовывать; прогресс и карточки ссылаются на них.
- Один шаг за запрос: не переходить к следующему этапу без подтверждения пользователя.
- UI/IA/схемы данных меняются только после дизайн-гейта (см. выше).
- Git: один логический шаг = один коммит; сообщения на английском в Conventional Commits (`feat:`, `fix:`, `docs:`, `chore:`). Не коммитить `node_modules`, `.expo`, `expo-env.d.ts`.
- Держи зависимости минимальными; предлагай альтернативы перед добавлением библиотеки.
- Обновляй этот файл и документацию, когда появляются реальные команды, структура и договорённости.
