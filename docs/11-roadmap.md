# 11. План реализации

Принцип: сначала тонкий вертикальный срез, который проверяет архитектуру, затем расширение. Не строить все системы сразу. Детальная разбивка по шагам — в [`15-implementation-plan.md`](15-implementation-plan.md).

## Фаза 0. Документация и решения

**Статус: выполнено (2026-11-21).**

- Продуктовое видение и ограничения.
- Архитектура, модель данных, course packs.
- Словарь, SRS, тексты.
- План, тестирование, ADR, открытые вопросы.
- `AGENTS.md` обновлён.

**Выход:** согласованная документация, с которой можно начинать скаффолд.

## Фаза 1. Скаффолд и фундамент

**Статус: app shell готов (2026-11-21).** Создан `blank-typescript`, добавлен Expo Router, 5 табов по IA, review/About как stack, тема и UI-компоненты. Проходят `typecheck`, `expo-doctor` и Android-export. Осталось: lint, тесты, БД.

**Цель:** запускаемое Expo-приложение на Android-телефоне через Expo Go.

Задачи:
- `create-expo-app` с TypeScript (`blank-typescript`).
- Добавить Expo Router и каркас навигации.
- Перестроить табы под IA: Главная, Курс, Словарь, Грамматика, Тексты; повторение — stack.
- Структура каталогов из [`03-architecture.md`](03-architecture.md).
- ESLint + Prettier + typecheck.
- Тема/токены, базовые компоненты.
- `expo-sqlite`: `user.db`, миграции, репозитории.
- Экран-заглушка главной.
- Проверка запуска на телефоне (same Wi-Fi, firewall).
- Зафиксировать точные команды в `AGENTS.md`.

**Критерии:**
- Приложение открывается на телефоне.
- `lint`, `typecheck` проходят.
- БД создаётся и мигрирует.
- Нет сетевых запросов.

**Риски:** Expo Go/сеть, версии SDK, миграции. Решение: минимальные зависимости, проверка на устройстве.

## Фаза 2. Грамматический вертикальный срез

**Статус: частично выполнено (2026-11-21).** Схема course pack, CLI и валидатор готовы. Осталось: контент `は`/`が`, экран урока, прогресс в SQLite, тесты.

**Цель:** полный офлайн-цикл урока.

Задачи:
- Схема course pack + Zod.
- Валидатор контента.
- 1–2 урока N5 (знакомые темы).
- Экран урока: объяснение, примеры.
- Три типа упражнений + проверка ответов.
- Обратная связь и итог.
- Сохранение прогресса/попыток.
- Unit-тесты проверки ответов и схемы.
- Ручной прогон на телефоне в авиарежиме.

**Критерии:**
- Урок проходится без сети.
- Прогресс сохраняется после перезапуска.
- Новый урок добавляется через JSON.
- Все три типа упражнений работают.

**Риски:** ambiguous content, верстка длинных примеров, IME (избегаем free-text).

## Фаза 3. Словарь и колоды

**Цель:** офлайн-словарь, связанный с колодой.

Задачи:
- Скрипт сборки `dictionary-ja-ru.db` из `jmdict-rus` (common-only).
- Метаданные, лицензия, checksum.
- Поиск: японский/русский, FTS5 + fallback.
- Экран статьи.
- Добавление в колоду (без планировщика).
- Состояние «уже в колоде».
- Экран «Источники».
- Тесты поиска и импорта.

**Критерии:**
- Поиск работает офлайн.
- Статья отображается.
- Добавление создаёт одну карточку.
- Атрибуция доступна.
- Размер БД измерен.

**Риски:** размер, покрытие русских глоссов, FTS5/trigram, лицензия.

## Фаза 4. SRS

**Цель:** повторение добавленных слов.

Задачи:
- `ts-fsrs` + обёртка.
- `card_srs`, `review_logs`.
- Очередь due, сессия повторения.
- Оценки и интервалы.
- Статистика минимум (due count).
- Тесты планировщика с фиксированным временем.
- Транзакционное обновление.

**Критерии:**
- Слово из словаря появляется в повторении.
- Оценка меняет срок.
- После перезапуска всё сохраняется.
- Дубликаты не создаются.

**Риски:** версия FSRS, часовые пояса, атомарность.

## Фаза 5. Тексты и чтение

**Цель:** текст → словарь → колода → повторение.

Задачи:
- Схема текста с токенами.
- Пайплайн токенизации на этапе сборки.
- Валидация покрытия текста токенами и ссылок на словарь.
- Ридер с фуриганой.
- Нижний лист словаря.
- Добавление в колоду с контекстом.
- Прогресс чтения (минимум).

**Критерии:**
- Текст открывается офлайн.
- Тап по слову открывает статью.
- Слово добавляется в колоду.
- Фуригана переключается.
- Нет runtime-токенизатора.

**Риски:** верстка фуриганы, качество токенизации, лицензии текстов, производительность.

## Фаза 6. Контент, полировка, релиз

**Цель:** приложение, которым можно пользоваться каждый день.

Задачи:
- Расширить N5-курс (знакомые темы).
- Добавить несколько коротких текстов.
- Настройки, «О приложении», источники.
- Экспорт/импорт прогресса.
- Оптимизация размера/скорости.
- Accessibility-проход.
- Иконка/сплэш/название.
- CI: lint/typecheck/test/content validation.
- EAS Build/APK для установки без Expo Go (позже).

**Критерии:**
- Стабильный ежедневный сценарий.
- Нет потери данных.
- Размер и скорость в бюджете.
- Лицензии и атрибуция в порядке.

## Фаза 7. Универсальность и расширения

- Второй язык как proof: небольшой пак (например, 20–50 слов) + адаптер.
- Полный словарь отдельным паком.
- Импорт/скачивание course packs.
- Визуальный конструктор курсов (только после стабилизации формата).
- iOS.
- C#-бэкенд/синхронизация (только при реальной необходимости).
- Аудио, кандзи-разбор, рукописный ввод.

## Порядок и зависимости

```text
0 docs
  → 1 scaffold
    → 1b app shell / IA
      → 2 grammar slice
        → 3 dictionary + decks
          → 4 SRS
            → 5 texts
              → 6 polish/release
                → 7 universality
```

Словарь можно начать параллельно с грамматикой после скаффолда, но не раньше стабилизации БД и миграций. SRS — после того, как есть карточки. Тексты — после словаря и SRS, чтобы сразу проверить полную связку.
