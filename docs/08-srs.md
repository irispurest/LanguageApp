# 08. SRS и колоды

## Роль

SRS превращает словарь и тексты в повторяемую практику. Пользователь добавляет слово из статьи или текста, а приложение решает, когда показать его снова.

## Алгоритм

Используем **FSRS** через [`ts-fsrs`](https://github.com/open-spaced-repetition/ts-fsrs).

- Версия библиотеки фиксируется в `package.json`.
- `ts-fsrs` v6 по умолчанию использует FSRS-7; модель и версия библиотеки независимы.
- Не писать собственный SRS-алгоритм.
- Параметры по умолчанию; оптимизация по журналу — позже.
- Планировщик — чистая обёртка в `src/core/srs/`; UI не знает формул.

`ts-fsrs` v6 требует Node.js >= 24 для сборки/оптимизатора; наше окружение — Node 24.21. Runtime-код — чистый TypeScript, работает в Hermes.

## Карточки

### Типы

| Тип | Вопрос | Ответ |
|---|---|---|
| `jp_to_ru` | Японское слово | Русское значение |
| `ru_to_jp` | Русское значение | Японское слово/чтение |
| `reading` | Кандзи | Кана |
| `grammar` | Конструкция/пример | Правило/перевод (позже) |

В MVP после словаря достаточно `jp_to_ru`; остальные типы добавляются постепенно.

### Создание

- Из статьи словаря.
- Из текста (с контекстом).
- Вручную (позже).
- Из грамматического урока (позже).

Правило дубликатов: одна карточка на `(dictionary_entry_id, prompt_type)`; для грамматики — `(grammar_point_id, prompt_type)`.

### Снимок

Карточка хранит `front`, `back`, `reading` — снимок на момент создания. Обновление словаря не должно ломать карточку. Если пользователь захочет обновить снимок — отдельное действие.

## Колоды

- Дефолтная колода создаётся при первом запуске.
- Колода «Из текстов» — опционально; можно складывать всё в одну.
- Пользовательские колоды — позже.
- В MVP не перегружать управлением колодами: одна основная + источник у карточки.

## Поток повторения

```text
Главная / «Повторить»
  → очередь due-карточек
    → карточка: вопрос
      → «Показать ответ»
        → ответ + контекст
          → Again / Hard / Good / Easy
            → FSRS пересчёт
              → сохранить карточку + review log
                → следующая
                  → итог
```

Правила:
- Оценка недоступна до показа ответа.
- После оценки карточка больше не показывается в этой сессии.
- «Again» возвращает карточку в обучение, но не в ту же секунду бесконечно.
- Показывать примерный следующий интервал для каждой оценки (полезно для обучения).
- Выход из сессии сохраняет уже отвеченные карточки.

## Запуск из курса

- После каждого урока — повторение слов этого урока/раздела.
- Лимит: до 10 слов за сессию; значение настраиваемое.
- Если due-карточек нет — блок повторения не показывается или показывает «на сегодня всё».
- Глобальная кнопка «Повторить» на Главной и в словаре запускает общую очередь.
- Встраивание в середину урока (`interleaved`) и повторение в конце раздела (`section_end`) — возможные расширения, не MVP.

Почему лимит: после урока не должно быть ощущения «ещё один длинный урок». 10 слов — короткая сессия, которую можно пропустить.

## Планирование

- `due` — epoch ms UTC.
- «Сегодня» определяется по локальной границе дня; для запроса due используем `due <= now`.
- Часовой пояс/перевод часов не должны ломать данные: пересчёт — при отображении, не в сохранённых полях.
- Новые карточки: небольшой дневной лимит позже; в MVP — очередь из добавленных.
- Просроченные карточки показываются первыми.
- Перемешивание внутри дня — позже.

## Данные

См. [`04-data-model.md`](04-data-model.md):
- `cards` — содержательная часть;
- `card_srs` — состояние планировщика;
- `review_logs` — неизменяемая история.

Обновление карточки и запись лога — в одной транзакции. Если запись лога не удалась, состояние карточки не должно «уехать» вперёд.

## Прогресс слова

Для личного словаря показываем не сырой процент, а статус:
- **Новое** — нет повторений;
- **Учится** — learning/relearning;
- **Закрепляется** — review, стабильность ниже порога;
- **Уверенно** — review, стабильность выше порога.

Прогресс вычисляется из `card_srs` (state/stability) и обновляется после каждого ответа. Точные пороги — после первых данных; UI не должен создавать ложную точность.

Если у слова несколько карточек, для MVP показываем прогресс основной карточки; агрегация — позже.

## Статистика

Позже:
- количество due/новых/изученных;
- точность по оценкам;
- streak;
- распределение интервалов;
- история по дням.

В MVP достаточно счётчика due на главной.

## Офлайн и время

- Всё работает без сети.
- Системное время может быть неверным; не блокировать приложение, но не позволять отрицательные интервалы.
- При переводе часов FSRS получает `now`; не пересчитывать старые логи задним числом.

## Связь со словарём и текстами

- Слово из текста: карточка сохраняет `context_sentence`; в повторении можно показать предложение с пропуском.
- Слово из словаря: контекста нет, показываем статью/значение.
- Если статья исчезла из новой версии словаря, карточка остаётся рабочей благодаря снимку; ссылка может стать неактивной.

## Тестирование

- Детерминированные тесты с фиксированным `now`.
- Фикстуры карточек для каждого состояния.
- Проверка: Again/Hard/Good/Easy дают ожидаемые `due`/`state`.
- Проверка: повторное добавление не создаёт дубликат.
- Проверка: review log и карточка обновляются атомарно.
- Проверка: due-запрос не зависит от часового пояса тестовой машины.

## Критерии приёмки

- Добавленное слово появляется в очереди.
- Оценка меняет срок следующего показа.
- После перезапуска состояние сохраняется.
- Дубликаты не создаются.
- Всё работает в авиарежиме.
- Журнал ответов позволяет позже пересчитать/оптимизировать параметры.

## Что не делаем в MVP

- Собственный алгоритм.
- Оптимизатор параметров на телефоне.
- Облачная синхронизация.
- Сложные дневные лимиты и статистика.
- Генерация карточек из всего текста автоматически.
