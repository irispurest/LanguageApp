# 15. Пошаговый план реализации

Это детальный план; высокоуровневые фазы — в [`11-roadmap.md`](11-roadmap.md). Правило: **один шаг за запрос**, каждый шаг заканчивается проверкой и коротким объяснением.

## Принципы

1. Сначала тонкий вертикальный срез, потом расширение.
2. Не строить будущую систему, пока текущая не проверена.
3. Контент — данные; UI не знает про конкретный урок.
4. Ядро не знает про японский; язык — в адаптере.
5. Офлайн — основной режим, а не «потом добавим».
6. Каждый шаг должен оставлять проект в запускаемом состоянии.
7. Перед шагом — план и подтверждение; после — проверка и объяснение.

## Шаг 2. Основные экраны и навигация

**Статус:** технически выполнен (2026-11-21). `typecheck`, `expo-doctor` (20/20) и Android-export проходят. Роутер, 5 табов, «О приложении», тема и UI-компоненты готовы как черновик. IA с тех пор изменилась — нужен шаг 2b.

**Цель:** получить запускаемый каркас приложения с табами и понятными экранами-состояниями.

**Задачи:**
- Установить Expo Router и зависимости.
- Настроить `main`, `scheme`, плагин, typed routes.
- Удалить старый `App.tsx`/`index.ts`.
- Создать `app/_layout.tsx`, `app/(tabs)/_layout.tsx`.
- Табы (исторический черновик): Главная, Учить, Словарь, Тексты, Повторение. Заменяются в шаге 2b.
- Экран «О приложении» через stack — показать переход и возврат.
- Тема, базовые компоненты (`Screen`, `Card`, `AppButton`, `EmptyState`, `Badge`).
- Строки в `src/i18n/ru.ts`.
- Экраны-состояния: «Скоро» для словаря/текстов/повторения, урок «В разработке».
- Проверки: `typecheck`, `expo-doctor`, Android-export.

**Критерии:**
- Приложение открывается на телефоне.
- Между табами можно переключаться.
- «О приложении» открывается и закрывается назад.
- Нет падений и «белых экранов».
- Русские строки не размазаны по JSX.
- Нет фейковой функциональности: словарь/тексты/SRS честно помечены как будущие.

**Не входит:**
- урок `は`/`が` и его контент;
- SQLite и прогресс;
- словарь и JMdict;
- SRS;
- анимации beyond Pressable feedback;
- lint/тесты (следующие шаги).

## Шаг 2b. Перестройка app shell под согласованную IA

**Статус:** выполнен (2026-11-21). 5 табов, review/About как stack, черновые экраны, `typecheck`/`expo-doctor`/Android-export проходят.

**Цель:** привести экраны к согласованной структуре, не добавляя контент/БД.

- 5 табов: Главная, Курс, Словарь, Грамматика, Тексты.
- Главная: следующий урок, повторение, краткая статистика, настройки.
- Курс: чистый список уровней/разделов/уроков (пока с placeholder-данными).
- Словарь: личный словарь по умолчанию + placeholder глобального поиска.
- Грамматика: один список с фильтром «Все/Пройдено» (placeholder).
- Тексты: один список с фильтром «Все/Прочитано» (placeholder).
- Убрать таб «Повторение»; review — stack-экран с заглушкой.
- «О приложении» — stack с Главной.
- Обновить строки/компоненты, не ломая тему.
- Проверки: `typecheck`, `expo-doctor`, Android-export.

**Не входит:** реальные уроки, схема контента, SQLite, словарь, SRS.

**Критерий:** навигация соответствует IA; все экраны — честные черновики без фейковых данных.

## Шаг 3. Схема контента и валидатор

**Статус:** выполнен (2026-11-21). Zod-схемы, manifest N5/N4/N3, `lessons/`/`grammar/`/`texts/`, CLI `content:new` (grammar), `content:validate`, тесты. `typecheck`/`content:validate`/`test:content`/`expo-doctor`/Android-export проходят.

**Цель:** контент становится данными, а не JSX.

- Zod-схемы: course pack, уровень, раздел, урок, упражнения, грамматическая тема, текст.
- Типы выводятся через `z.infer`; discriminated unions для типов урока/упражнений.
- `content/ja/manifest.json` с уровнями N5/N4/N3 и разделами.
- Каталоги `lessons/`, `grammar/`, `texts/`; lesson ссылается на grammar/text ID.
- `scripts/validate-content.ts` + `scripts/content-new.ts` (CLI).
- Generated `content/ja/index.ts` для статических импортов.
- Тесты схемы/валидатора.

**Критерий:** невалидный урок не проходит проверку; CLI создаёт урок и вставляет его в нужный раздел; валидный контент загружается.

## Шаг 4. Контент урока `は`/`が`

**Статус:** следующий.

**Цель:** знакомый пользователю урок, который проверяет приложение.

- Объяснение `は` vs `が` на русском.
- Примеры с чтением и переводом.
- 5–7 упражнений трёх типов.
- Проверка естественности и однозначности.
- `packVersion`/ID.

**Критерий:** урок можно прочитать, но пока без полноценного прохождения (UI — следующий шаг).

## Шаг 5. Экран урока и упражнения

**Цель:** полный проход урока.

- Экран урока: секции, примеры, прогресс.
- Компоненты трёх упражнений.
- Чистая проверка ответов.
- Обратная связь, итог, повтор.
- Навигация «назад/дальше» с сохранением состояния.

**Критерий:** урок проходится за 3–7 минут; все типы упражнений работают.

## Шаг 6. SQLite и прогресс

**Цель:** прогресс переживает перезапуск.

- `expo-sqlite`, `user.db`, миграции.
- Таблицы прогресса/попыток/сессий.
- Репозитории.
- Сохранение после каждого ответа.
- Тесты миграций.

**Критерий:** закрыл приложение — прогресс на месте; миграция не теряет данные.

## Шаг 7. Качество: lint, тесты, CI

**Цель:** защитить ядро от регрессий.

- ESLint + Prettier.
- Jest/React Native Testing Library.
- Тесты проверки ответов, схем, миграций.
- GitHub Actions: lint/typecheck/test/content validation.
- Команды в `AGENTS.md`.

**Критерий:** CI зелёный; новый урок/упражнение ломает тест, если схема нарушена.

## Шаг 8. Словарь

**Цель:** офлайн-японско-русский словарь.

- Скрипт сборки `dictionary-ja.db` из JMdict-rus common-only.
- Metadata/checksum/лицензия.
- FTS5 + fallback.
- Экран поиска и статьи.
- Экран «Источники».
- Тесты поиска.

**Критерий:** поиск работает без сети; статья открывается; лицензия доступна.

## Шаг 9. Колоды и добавление слов

**Цель:** слово из словаря можно сохранить.

- `decks`, `cards`, `card_srs` (начальное состояние).
- Добавление/дубликаты/состояние «уже в колоде».
- Снимок слова.
- Экран колоды (минимум).

**Критерий:** добавление создаёт одну карточку; после перезапуска она на месте.

## Шаг 10. SRS

**Цель:** повторение добавленных слов.

- `ts-fsrs`, обёртка планировщика.
- Due-очередь, сессия, оценки.
- `review_logs`.
- Мини-статистика.
- Детерминированные тесты.

**Критерий:** оценка меняет срок; всё офлайн; логи сохраняются.

## Шаг 11. Тексты

**Цель:** текст → словарь → колода → повторение.

- Схема текста с токенами.
- Build-time токенизация.
- Ридер, фуригана, тап по слову.
- Нижний лист словаря.
- Добавление с контекстом.
- Прогресс чтения.

**Критерий:** полная связка работает офлайн.

## Шаг 12. Полировка и релиз

- Контент N5, несколько текстов.
- Настройки, «О приложении», экспорт/импорт.
- Размер/скорость/accessibility.
- Иконка/название.
- EAS build/APK.

**Критерий:** приложение можно ставить и использовать ежедневно.

## Шаг 13. Универсальность

- Второй язык как proof.
- Полный словарь отдельным паком.
- Импорт паков.
- Конструктор курсов — только после стабилизации формата.
- iOS/бэкенд — отдельные решения.

## Граф зависимостей

```text
0 docs
  → 1 scaffold
    → 2 screens/navigation
      → 3 content schema
        → 4 は/が content
          → 5 lesson UI
            → 6 SQLite progress
              → 7 quality
                → 8 dictionary
                  → 9 decks
                    → 10 SRS
                      → 11 texts
                        → 12 polish
                          → 13 universality
```

Шаги 3 и 8 могут частично идти параллельно после стабилизации БД, но не раньше шага 2.

## Definition of Done для шага

- Код собирается и запускается.
- `typecheck` проходит.
- Новые команды/структура отражены в `AGENTS.md`/docs.
- Есть ручная проверка на телефоне или объяснение, почему она отложена.
- Нет незапланированных функций «на будущее».
- Пользователь понимает, что изменилось и как это проверить.
