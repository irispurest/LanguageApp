# 06. Грамматические уроки и тесты

## Роль в продукте

Грамматика — первый вертикальный срез. Он проверяет не только контент, но и весь цикл: загрузка урока → объяснение → упражнение → проверка → сохранение → результат. Словарь, SRS и тексты переиспользуют те же принципы.

## Грамматический каталог

Грамматическая тема — отдельный объект (`grammar/...`), а не только часть урока. Урок грамматики ссылается на `grammarPointIds`. Вкладка «Грамматика» показывает весь каталог, включая темы вне текущего курса; «Пройдено» — отдельный статус.

Статус «пройдено» ставится автоматически после урока или вручную на экране темы. Один источник контента, без дублирования explanation в уроке и каталоге.

## Структура урока

1. **Вступление**: цель урока, 1–2 предложения.
2. **Объяснение**: короткие абзацы, примеры, замечания.
3. **Упражнения**: 5–7 заданий, разные типы.
4. **Итог**: счёт, разбор ошибок, кнопка «Повторить»/«Готово».

Урок должен проходиться за 3–7 минут.

## Поток экрана

```text
Список уроков
  → Вступление
    → Блок объяснения
      → Пример
        → Упражнение 1
          → Ответ
            → Обратная связь
              → Упражнение 2 ...
                → Итог
                  → Главная / Повторить
```

Правила:
- Выход из урока сохраняет прогресс.
- «Назад» не теряет уже данные ответы.
- Ответ нельзя отправить дважды случайно.
- После ответа показывается объяснение, затем «Дальше».
- В итоге видно, какие упражнения были с ошибками.

## Типы упражнений MVP

### 1. Выбор варианта
- 3–4 варианта.
- Один правильный.
- После ответа: подсветка, объяснение, кнопка «Дальше».
- Не делать варианты, где два ответа грамматически допустимы без контекста.

### 2. Пропуск из банка слов
- Один пропуск.
- Банк из 3–5 вариантов.
- Пользователь выбирает слово, оно подставляется в пропуск.
- Проверка по строке с нормализацией.
- В объяснении — почему именно эта форма.

### 3. Упорядочивание
- 4–7 токенов.
- Пользователь собирает предложение.
- Проверка по исходным индексам.
- Пунктуация — отдельный токен.
- В объяснении — базовая структура предложения.

## Обратная связь

- Правильно: короткое подтверждение + объяснение (не только «верно»).
- Неправильно: показать правильный ответ и объяснение, не ругать.
- Можно повторить упражнение; в прогресс идёт последняя попытка, история попыток сохраняется.
- Не использовать случайные «весёлые» сообщения, которые перекрывают смысл.

## Прогресс и завершение

- `lesson_progress` обновляется после каждого ответа.
- `lesson_sessions` фиксирует проход.
- `exercise_attempts` хранит ответы и время.
- Завершённый урок можно пройти снова; счёт и история сохраняются.
- «Продолжить» ведёт к последнему незавершённому упражнению.

## Контентные правила

- Первый курс — знакомые N5-темы: пользователь проверяет приложение, а не учит новое.
- Один урок — одна грамматическая точка.
- Объяснение — по-русски, коротко.
- Примеры — с японским, чтением и переводом.
- Использовать вежливую речь как основу, если тема не требует иного.
- Не смешивать в одном упражнении несколько новых правил.
- Избегать предложений, где ответ зависит от редкого контекста.
- Проверять чтение кандзи и фуригану.

## Первый урок

Первый урок выбран — частицы `は` и `が`. Тема знакома пользователю на N5+, поэтому позволяет проверять приложение и упражнения, а не изучать новое правило.

Следующие кандидаты:
1. `です` / `ます` — вежливая связка и глагольная форма.
2. Прошедшее время вежливых форм.
3. Частицы `を`, `に`, `で`.

План урока `は`/`が` и упражнения к нему составляются отдельным шагом.

## Пример плана другого урока: «です / ます»

1. Что такое вежливая речь.
2. Существительное + `です`.
3. Глагол + `ます`.
4. Отрицание (`ではありません`, `ません`) — если пользователь подтвердит.
5. Упражнения:
   - выбор `です`/`ます`/`だ`;
   - пропуск `勉強します`;
   - порядок слов в предложении.
6. Итог и объяснение ошибок.

## Критерии приёмки

- Урок открывается из списка.
- Все блоки отображаются без сырого JSON.
- Три типа упражнений работают.
- Ответы проверяются корректно.
- Ошибки объясняются.
- Прогресс сохраняется после перезапуска.
- Урок проходится без сети.
- Валидатор не пропускает заведомо сломанный урок.

## Связь с SRS

В MVP грамматика не попадает в SRS. Позже грамматическая точка может стать карточкой:
- `grammar_point_id` в `cards`;
- тип `grammar`;
- вопрос — конструкция/пример, ответ — правило/перевод;
- планировщик тот же FSRS.

Схема данных уже поддерживает это, но реализация — после стабилизации словарных карточек.
