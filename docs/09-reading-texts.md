# 09. Тексты и чтение

## Роль

Тексты дают язык в контексте. Главная связка: пользователь читает → нажимает незнакомое слово → открывает словарь → добавляет в колоду → повторяет. Это ключевая функция, ради которой словарь и SRS должны быть связаны.

## Формат текста

```json
{
  "schemaVersion": 1,
  "id": "ja-ru-n5-self-intro",
  "courseId": "ja-ru",
  "level": "N5",
  "title": "Знакомство",
  "body": "私は学生です。",
  "translation": "Я студент.",
  "tokens": [
    {
      "surface": "私",
      "lemma": "私",
      "reading": "わたし",
      "pos": "pron",
      "start": 0,
      "end": 1,
      "entryIds": ["1000000"]
    }
  ],
  "source": {
    "type": "original",
    "license": "proprietary",
    "attribution": ""
  }
}
```

Требования:
- `tokens` покрывают `body` без пропусков (проверка при сборке).
- `start`/`end` — индексы в строке в UTF-16 code units, как в `String.prototype.slice` (так проще сверять с JS).
- `entryIds` — кандидаты JMdict, найденные при сборке.
- Пунктуация — отдельные токены.
- Перевод — на русском.

## Токенизация

Токенизация выполняется **на этапе сборки контента**, не на телефоне.

Варианты:
- MeCab/SudachiPy (Python) — точнее, требует установки для сборки;
- `kuromoji` (Node) — проще для JS-пайплайна, словарь в комплекте;
- ручная разметка для коротких текстов.

Рекомендация: начать с `kuromoji` или SudachiPy в скрипте, результат проверять вручную. Runtime-токенизатор не добавляем: он тяжёлый и усложняет офлайн-бандл.

Для каждого токена:
- `surface` — как в тексте;
- `lemma` — словарная форма (важно для глаголов/прилагательных);
- `reading` — фуригана;
- `pos` — часть речи;
- `entryIds` — сопоставление с JMdict по написанию/чтению/лемме.

## Ридер

### Отображение
- Текст разбит на токены.
- Фуригана показывается над токенами с кандзи; переключатель в настройках/шапке.
- Пунктуация не получает фуригану.
- Перевод текста — по кнопке/внизу, не перегружать экран.

### Тап по слову
1. Найти `entryIds` токена.
2. Открыть нижний лист:
   - написание, чтение, значения;
   - кнопка «Добавить в колоду»;
   - состояние «уже в колоде».
3. Если кандидатов несколько — список статей.
4. Если ничего не найдено — «Нет в словаре» + кнопка ручного поиска.

### Прогресс
- Позиция чтения и завершение — в `text_progress`.
- В MVP можно без сложного прогресса, но структура данных готова.

## Фуригана и верстка

React Native не поддерживает HTML `<ruby>`. Нужен кастомный компонент:
- каждый токен — колонка: чтение сверху, поверхность снизу;
- перенос строк по токенам, а не по символам;
- аккуратно с пунктуацией и длинными предложениями;
- проверять на маленьких экранах и при увеличенном шрифте.

Альтернатива для MVP: показывать чтение в скобках после слова или во всплывающей подсказке. Но целевой UX — фуригана над кандзи.

## Контент

- Первые тексты — короткие (2–5 предложений), N5, знакомые темы.
- Собственные тексты или Tatoeba с атрибуцией.
- Не использовать copyrighted тексты без разрешения.
- Проверять естественность японского и корректность чтений.
- Не смешивать в одном тексте много незнакомой лексики.

## Производительность

- Токены рендерить эффективно; для длинных текстов — виртуализация.
- Не выполнять поиск по словарю на каждый кадр; кэшировать результаты.
- Нижний лист словаря открывать быстро; запрос по одному `entry_id`.
- Длинные статьи словаря — с прокруткой, без загрузки всех примеров сразу.

## Критерии приёмки

- Текст отображается без сети.
- Фуригана включается/выключается.
- Тап по слову открывает словарь.
- Слово добавляется в колоду с контекстом.
- Токены покрывают текст, валидатор это проверяет.
- Нет runtime-токенизатора и сетевых запросов.
