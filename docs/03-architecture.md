# 03. Архитектура

## Контекст

Приложение — офлайн-клиент на React Native + Expo + TypeScript. Бэкенда в MVP нет. Основные данные: контент (уроки, тексты), словарь, прогресс и карточки повторения.

Ключевое ограничение: первый этап должен работать в **Expo Go** на Android-телефоне, без кастомных нативных модулей и без локальной сборки Android.

## Два контура: runtime и build-time

### Runtime (на телефоне)
- Expo Router строит навигацию.
- Course packs читаются из локальных JSON.
- `user.db` хранит прогресс, карточки и журнал ответов.
- `dictionary-ja-ru.db` открывается только на чтение из asset.
- Сетевых запросов нет.

### Build-time (на компьютере / в CI)
- Валидация course packs по Zod-схемам.
- Сборка `dictionary-ja-ru.db` из JSON-релиза JMdict.
- Проверка ссылок токенов на словарь.
- Линт, typecheck, тесты.
- Генерация ассетов не коммитится вручную.

## Почему две базы данных

1. **Словарь — большой и read-only.** Его можно заменить новым файлом, не трогая прогресс.
2. **Прогресс — маленький и read-write.** Его нужно мигрировать и резервировать.
3. **Разные жизненные циклы.** Обновление словаря не должно требовать миграции пользовательских данных.
4. **Безопасность данных.** Ошибка в сборке словаря не должна повредить `user.db`.

## Почему контент не импортируется в SQLite

Course packs небольшие. Их проще читать как JSON:
- меньше миграций;
- контент можно редактировать и валидировать отдельно;
- прогресс ссылается на стабильные ID, а не на строки БД;
- обновление контента не требует пересборки пользовательской схемы.

Если позже появятся большие паки или сложный поиск по контенту, можно добавить кэш/индекс, но не раньше.

## Потоки данных

### Запуск
1. Открыть `user.db`, выполнить миграции.
2. Проверить/открыть `dictionary-ja-ru.db` (read-only).
3. Загрузить `content/ja-ru/manifest.json`.
4. Показать главную: продолжить урок, due-повторения, быстрые ссылки.

### Урок грамматики
1. Загрузить JSON урока.
2. Показать блоки объяснения и примеры.
3. Для каждого упражнения: ответ → чистая функция проверки → сохранить попытку → обратная связь.
4. По завершении сохранить прогресс и показать итог.
5. «Продолжить» на главной ведёт к последнему незавершённому уроку.

### Словарь
1. Пользователь вводит запрос.
2. Поиск идёт по индексам и FTS5, выдача ограничена.
3. Открывается статья.
4. «Добавить в колоду» создаёт карточку (с контекстом, если слово пришло из текста).
5. Повторное добавление не создаёт дубликат.

### Текст
1. Загрузить JSON с готовыми токенами.
2. Отрисовать токены, при включённой фуригане — чтение.
3. Тап по токену: найти `entry_id` в словаре.
4. Открыть нижний лист со статьёй.
5. «Добавить в колоду» сохраняет слово, чтение и предложение-контекст.

### Повторение
1. Запрос due-карточек из `user.db`.
2. Показ карточки, ответ, оценка.
3. `ts-fsrs` пересчитывает состояние.
4. Транзакционно обновить карточку и записать review log.
5. Следующая карточка или итог.

## Ключевые технические решения

- **Expo Router** для навигации: файловая структура, typed routes. Основные разделы — JavaScript `Tabs`; «О приложении» — root `Stack`. Route-файлы тонкие, экраны — в `src/features/`.
- **expo-sqlite** для обеих БД. FTS5 включён; в Expo Go доступен. Встроенный DevTools inspector (Shift+M в Expo CLI) позволяет смотреть БД.
- **Без ORM в MVP.** Явные SQL-запросы и типизированные репозитории. Drizzle можно рассмотреть позже, если схема вырастет.
- **Zod** для валидации course packs и границ данных.
- **ts-fsrs** для SRS; без собственного алгоритма.
- **Никаких кастомных нативных модулей в MVP.** Всё, что не работает в Expo Go, откладывается.
- **Стили:** `StyleSheet` + токены темы; без тяжёлого UI-kit.
- **Состояние:** локальный React state + хуки/репозитории; без Redux/Zustand, пока нет доказанной необходимости.
- **Строки UI:** язык системы с fallback на русский; поддерживается только `ru`, один слой сообщений в `src/i18n/`. Content source language (`ru`) не равен UI locale.

## Обработка ошибок

- Невалидный course pack: ошибка на этапе сборки/тестов, а не в рантайме.
- Отсутствует `dictionary-ja-ru.db`: в dev — понятное сообщение «запусти сборку словаря»; в release — ошибка сборки.
- Токен не найден в словаре: fallback по лемме/чтению, затем «не найдено» без падения.
- Ошибка миграции: показать сообщение, не удалять БД, оставить путь к экспорту/логам.
- Ошибка одного урока: изолировать, остальное приложение работает.

## Производительность

- Не загружать словарь целиком в JS; только запросы с лимитом.
- Индексы для каны/кандзи, FTS5 для поиска.
- Токены текста рендерить эффективно; для длинных текстов — виртуализация/постраничность.
- Мемоизировать тяжёлые преобразования.
- Измерять размер бандла и БД на каждом этапе.

## Будущий бэкенд

Если появится синхронизация:
- стек C#/.NET;
- API для прогресса/контента, без обязательного аккаунта в MVP;
- экспорт/импорт JSON как основа контракта;
- офлайн остаётся основным режимом, сервер — дополнением.

Не добавлять бэкенд, auth и sync без явного запроса.
