# 05. Course packs

## Что это

Course pack — версионированный набор контента для языка: манифест, уроки, тексты, упражнения. Контент описывается данными, а не JSX. Новый урок должен добавляться без правки экранов.

## Структура

```text
content/ja/
  manifest.json
  lessons/
    ja-n5-desu-masu.json
    ja-n5-wa-ga.json
  grammar/
    ja-grammar-desu-masu.json
    ja-grammar-wa-ga.json
  texts/
    ja-n5-self-intro.json
  index.ts              # generated: статические import'ы для Metro
```

`index.ts` генерируется скриптом валидации, потому что Metro/React Native не поддерживает динамический `require` с переменным путём. Позже, для скачиваемых паков, загрузка пойдёт через `expo-file-system`.

## Манифест

```json
{
  "schemaVersion": 1,
  "packId": "ja",
  "packVersion": "0.1.0",
  "language": "ja",
  "title": "Японский",
  "description": "Единый курс с уровнями N5/N4/N3",
  "license": "proprietary",
  "attribution": [],
  "levels": [
    {
      "id": "n5",
      "code": "N5",
      "title": "Начальный",
      "sections": [
        {
          "id": "n5-particles",
          "title": "Частицы",
          "lessons": ["ja-n5-wa-ga", "ja-n5-vocab-1"],
          "review": {
            "policy": "after_lesson",
            "maxWords": 10
          }
        }
      ]
    }
  ],
  "grammar": ["ja-grammar-wa-ga", "ja-grammar-desu-masu"],
  "texts": ["ja-n5-self-intro"]
}
```

Правила:
- `packId` и `language` обязательны; один пак — один курс.
- `schemaVersion` — версия формата, не версия контента.
- `packVersion` — SemVer контента.
- `levels[].sections[].lessons` — ordered-список ID уроков; порядок задаётся здесь.
- ID урока уникален и совпадает с `id` внутри файла.
- `file` — путь относительно пака; уроки лежат в `lessons/`.
- `review.policy` — как встраивать повторение: `after_lesson`, `interleaved`, `section_end`, `none`; `review.maxWords` — лимит слов за сессию (см. ниже).
- `grammar`/`texts` — каталоги для вкладок «Грамматика»/«Тексты». Уроки ссылаются на их ID.
- `license`/`attribution` — для сторонних материалов.

### Грамматика и тексты — отдельные каталоги

Это важно для справочных вкладок:
- грамматическая тема существует как отдельный объект (`grammar/ja-grammar-wa-ga.json`);
- текстовый материал — отдельный объект (`texts/...`);
- урок грамматики ссылается на `grammarPointIds`, урок текста — на `textId`;
- вкладка «Грамматика» показывает все темы, даже если урок по ним ещё не пройден;
- вкладка «Тексты» показывает все тексты, а не только входящие в текущий раздел.

Не дублировать explanation/текст внутри урока и каталога: один источник, урок ссылается на него.

### Уровни и разделы

- В MVP один курс «Японский» с уровнями N5/N4/N3.
- Уровень содержит разделы, раздел — упорядоченный список уроков.
- Новый урок вставляется добавлением ID в нужный раздел и файла в `lessons/`.
- Перемещение урока — изменение порядка в `lessons` массиве; ID не меняется.
- Пустые уровни/разделы допустимы, но не показываются как «сломанные».

### Типы уроков

| Тип | Данные | После завершения |
|---|---|---|
| `grammar` | `grammarPointIds`, блоки объяснения/примеров | тема → «пройдено» |
| `vocabulary` | `wordIds`, блоки слов | слова → личный словарь + карточки |
| `text` | `textId`, вопросы | текст → «прочитан» |
| `listening` | позже | позже |

Отдельного типа `review` нет: повторение встраивается через `reviewPolicy` или запускается с Главной/из словаря.

## Урок

```json
{
  "schemaVersion": 1,
  "id": "ja-n5-desu-masu",
  "type": "grammar",
  "language": "ja",
  "level": "N5",
  "title": "です / ます",
  "subtitle": "Вежливая речь",
  "objective": "Понять, как строится вежливое утверждение.",
  "grammarPointIds": ["ja-grammar-desu-masu"],
  "estimatedMinutes": 5,
  "tags": ["copula", "polite"],
  "sections": [
    {
      "type": "paragraph",
      "text": "В вежливой речи существительное и прилагательное связываются с помощью です."
    },
    {
      "type": "example",
      "japanese": "私は学生です。",
      "reading": "わたしはがくせいです。",
      "translation": "Я студент."
    },
    {
      "type": "note",
      "text": "Частица は читается как わ."
    }
  ],
  "exercises": [
    {
      "id": "ex-desu-01",
      "type": "multiple_choice",
      "prompt": "Выбери правильный вариант.",
      "question": "私は学生___。",
      "options": ["です", "ます", "だ"],
      "correctIndex": 0,
      "explanation": "С существительным используется です."
    }
  ]
}
```

### Блоки урока

| Тип | Поля | Назначение |
|---|---|---|
| `paragraph` | `text` | Абзац объяснения |
| `example` | `japanese`, `reading`, `translation` | Пример с чтением и переводом |
| `note` | `text` | Важное замечание |
| `table` | `headers`, `rows` | Небольшая таблица форм |

Не использовать Markdown/HTML в MVP: типизированные блоки проще валидировать и рендерить.

## Упражнения

Общие поля:
- `id` — стабильный, уникальный в уроке;
- `type` — тип;
- `prompt` — инструкция;
- `explanation` — объяснение после ответа.

### `multiple_choice`

```json
{
  "id": "ex-01",
  "type": "multiple_choice",
  "prompt": "Выбери правильную форму.",
  "question": "私は学生___。",
  "options": ["です", "ます", "だ"],
  "correctIndex": 0,
  "explanation": "С существительным используется です."
}
```

Проверка: `answerIndex === correctIndex`.

### `cloze`

```json
{
  "id": "ex-02",
  "type": "cloze",
  "prompt": "Вставь пропущенное слово.",
  "sentence": "私は毎日日本語を{{blank}}。",
  "bank": ["勉強します", "勉強する", "勉強した"],
  "correctAnswers": ["勉強します"],
  "explanation": "Вежливая форма настоящего времени — 勉強します."
}
```

Правила:
- ровно один `{{blank}}` в MVP;
- `bank` — варианты, из которых выбирает пользователь;
- `correctAnswers` — допустимые строки (можно несколько вариантов написания);
- сравнение после нормализации пробелов/Unicode.

### `ordering`

```json
{
  "id": "ex-03",
  "type": "ordering",
  "prompt": "Собери предложение.",
  "tokens": ["私は", "毎日", "日本語を", "勉強します", "。"],
  "correctOrder": [0, 1, 2, 3, 4],
  "explanation": "Прямой порядок: подлежащее → обстоятельство → дополнение → сказуемое."
}
```

Правила:
- `correctOrder` — перестановка индексов `tokens`;
- UI перемешивает токены, но проверка идёт по исходным индексам;
- пунктуация — отдельный токен.

### Будущие типы

`matching`, `typing`, `listening`, `sentence_choice`. Не добавлять в MVP, пока три текущих типа не стабильны.

## Повторение в курсе

Повторение — не отдельный урок, а политика раздела/урока:

| `review.policy` | Поведение |
|---|---|
| `after_lesson` | после итога урока показать due-карточки слов/темы; можно пропустить |
| `interleaved` | вставить due-карточки между упражнениями урока (позже) |
| `section_end` | показать повторение раздела в конце (позже) |
| `none` | не встраивать |

Дефолт для MVP — `after_lesson` с `maxWords: 10`. Политика задаётся в разделе; урок может переопределить. Общий review-режим один, не дублируется по типам уроков.

Почему не отдельный урок: due-очередь динамическая, а «урок» — статический контент. Смешивать их — значит хранить в контенте состояние пользователя.

Почему лимит: после урока не должно быть ощущения «ещё один длинный урок». Лимит можно поднять/понизить в настройках или контенте позже.

## Проверка ответов

Проверка — чистая функция в `src/core/exercises/`:
- не знает про React и БД;
- принимает упражнение и ответ;
- возвращает `{ correct: boolean, normalizedAnswer, expected }`;
- покрыта unit-тестами.

Для MVP нет свободного ввода по-японски: IME делает проверку и UX непредсказуемыми. Сначала выбор, банк слов и порядок.

## Валидация

Скрипт `scripts/validate-content.ts` (появится после скаффолда) проверяет:
- Zod-схему манифеста, уровней, разделов, уроков и текстов;
- уникальность ID и ссылок уровень → раздел → урок;
- `review.policy` — допустимое значение; `review.maxWords` — положительное число;
- `correctIndex` в диапазоне;
- `correctOrder` — валидная перестановка;
- наличие `explanation`;
- непустые `sections`/`exercises`;
- ссылки на словарь/грамматику/тексты;
- наличие всех `grammar`/`texts` ID из манифеста и уроков;
- соответствие `level/section` в манифесте и уроке;
- отсутствие дубликатов файлов.

Ошибки должны быть понятными и указывать файл/поле.

## Версионирование и стабильность

- `schemaVersion` меняется при несовместимом изменении формата.
- Приложение поддерживает диапазон версий; неизвестная версия — понятная ошибка.
- ID уроков/упражнений/текстов **не переименовывать**: прогресс и карточки ссылаются на них.
- Если урок удалён, его прогресс остаётся в БД; урок помечается архивным.
- `packVersion` увеличивается при любом изменении контента.

## Авторский процесс

CLI (шаг 3; пока только `grammar`):

```bash
npm run content:new -- --type grammar --level N5 --section n5-particles --title "は и が"
npm run content:validate
```

1. CLI создаёт JSON-шаблон урока и добавляет ID в нужный раздел.
2. Заполнить объяснение, примеры и упражнения.
3. Запустить валидацию.
4. Проверить урок в приложении на телефоне.
5. Обновить `packVersion`.

Визуального конструктора в MVP нет. Это осознанно: сначала стабилизируем формат.
