# 07. Словарь

## Роль в продукте

Словарь — не отдельная вкладка «на всякий случай», а связующее звено:
- из текста можно нажать на слово и открыть статью;
- из статьи можно добавить слово в колоду;
- карточка сохраняет контекст и потом участвует в SRS;
- поиск работает офлайн.

## Источник данных

Выбран **JMdict** в редакции `jmdict-rus` из проекта [`scriptin/jmdict-simplified`](https://github.com/scriptin/jmdict-simplified).

Проверенные данные релиза `3.6.2+20261116213322` (dictDate `2026-11-16`):

| Показатель | Значение |
|---|---|
| Всего статей с русскими глоссами | 69 419 |
| «Common»-статей | 18 537 |
| Полный JSON | ~36.5 МБ |
| Common-only JSON | ~10.1 МБ |
| ID статей | стабильные строки JMdict |

Почему он:
- открытая лицензия и понятная атрибуция;
- русские переводы, а не только английские;
- стабильные ID, удобные для ссылок из текстов и карточек;
- готовый JSON, не нужно парсить XML;
- есть common-only подмножество для небольшого стартового бандла.

Ограничения:
- это не полный JMdict: статьи без русских глоссов отсутствуют;
- качество/полнота русских переводов может различаться;
- примеры предложений в русской редакции не входят;
- лицензия требует атрибуции, share-alike для производной БД и процедуры обновления.

## Лицензия и атрибуция

JMdict и производные файлы распространяются по **CC BY-SA 4.0** (EDRDG license).

Обязательно:
- указать источник и авторов в приложении (экран «Источники»/«О приложении»), а не только на стартовом экране;
- дать ссылки на EDRDG и JMdict;
- включить текст лицензии или ссылку на неё;
- не заявлять авторские права на данные словаря;
- производная база (`dictionary-ja.db`) распространяется под той же лицензией;
- предусмотреть процедуру регулярного обновления словаря;
- сохранить атрибуцию `jmdict-simplified` как источника конвертации.

Код приложения не обязан быть под CC BY-SA, но данные словаря — да. Коммерческое использование разрешено; EDRDG предлагает донат, но не требует его.

## Пайплайн сборки

```text
GitHub Release jmdict-rus-*.json.zip
        │
        ▼
scripts/build-dictionary.ts
  ├── скачать/распаковать (pinned release)
  ├── проверить checksum
  ├── отфильтровать common-only (для стартового бандла)
  ├── нормализовать в SQLite
  ├── построить FTS5-индекс
  ├── записать metadata (source, version, dictDate, license)
  └── assets/dictionary/dictionary-ja.db
```

Правила:
- raw JSON и собранная БД не коммитятся вручную;
- версия релиза и checksum фиксируются в скрипте/конфиге;
- сборка воспроизводима;
- при обновлении меняется версия и дата в `metadata`;
- приложение не пишет в `dictionary-ja.db`.

## Схема

Подробно — в [`04-data-model.md`](04-data-model.md). Кратко:
- `entries` — статья, `jmdict_id`, `is_common`;
- `entry_kanji`, `entry_kana` — написания и чтения;
- `entry_senses` — значения и части речи;
- `entry_glosses` — русские переводы;
- `entry_fts` — FTS5 trigram по кандзи/кане/глоссам;
- `metadata` — версия, дата, лицензия.

## Поиск

### По-японски
1. Точное совпадение по кандзи или кане.
2. Префикс по кане/кандзи.
3. FTS5 по смешанному индексу.
4. Fallback `LIKE` для запросов короче 3 символов.

### По-русски
- FTS5 по глоссам.
- Без стемминга в MVP: пользователь ищет по началу слова/форме; это ограничение фиксируем в UI.
- Позже можно добавить нормализацию/русский стеммер, но не в первом срезе.

### Ранжирование
1. Точное совпадение.
2. Common-статья.
3. Префикс.
4. FTS rank.
5. Ограничение выдачи (например, 30–50 результатов).

### Производительность
- Не загружать все статьи в JS.
- Запросы с `LIMIT`, индексы, FTS.
- Для длинных списков — пагинация/бесконечная прокрутка.

## Экран статьи

Показывать:
- основное написание и чтение;
- все варианты кандзи/каны;
- значения по частям речи;
- пометки (common, разговорное, устаревшее и т.п.);
- кнопку «Добавить в колоду» / «Уже в колоде»;
- источник/лицензию в «О приложении», не на каждой карточке.

Позже:
- примеры предложений (Tatoeba/собственные);
- аудио;
- кандзи-разбор.

## Личный словарь и прогресс

Вкладка «Словарь» по умолчанию открывает **личный словарь**, а не весь JMdict.

- Личный словарь = слова, для которых есть карточка (добавлены из урока, текста или вручную).
- Сортировка: по времени добавления (`created_at`) / по прогрессу / по алфавиту.
- Группировку по уровню не делаем: уровень не гарантирован для всех слов.
- Поиск переключается на глобальный JMdict; найденные личные слова помечаются цветом/бейджем и прогрессом.
- Полный глобальный словарь не рендерится списком: только поиск и выдача с лимитом.
- «Повторить слова» запускает общий review-режим.

### Прогресс изучения слова

Источник истины — состояние FSRS (`card_srs`), а не отдельное вручную обновляемое поле.

Предлагаемая шкала без «сырых» процентов:
- **Новое** — карточка создана, но ещё не повторялась;
- **Учится** — learning/relearning или мало повторений;
- **Закрепляется** — review, стабильность растёт;
- **Уверенно** — большой интервал/стабильность.

UI: 4-сегментная полоса или бейдж. Точные пороги — после первых реальных повторений; не показывать псевдоточный процент.

В MVP — одна карточка на слово (`jp_to_ru`). Если позже появятся несколько типов карточек, прогресс можно агрегировать (минимум/среднее) — отдельное решение.

## Интеграция с текстами

Текст хранит токены, у каждого есть:
- `surface` — как в тексте;
- `lemma` — словарная форма;
- `reading` — чтение;
- `entryIds` — кандидаты JMdict, найденные при сборке контента.

Тап по токену:
1. Если есть `entryIds`, открыть первый/список кандидатов.
2. Если нет, искать по `lemma`/`reading`.
3. Если не найдено — показать «нет в словаре» и предложить поиск вручную.

Это позволяет не запускать морфологический анализатор на телефоне.

## Добавление в колоду

При добавлении:
- создать карточку с `dictionary_entry_id`, `front`, `back`, `reading`;
- сохранить `context_text_id`, `context_token_index`, `context_sentence`, если слово пришло из текста;
- не создавать дубликат для той же статьи и того же `prompt_type`;
- если карточка уже есть, показать «Уже в колоде» и, возможно, «Показать карточку».

Типы карточек в MVP SRS: `jp_to_ru`, `ru_to_jp`, `reading`. Выбор типа — позже; по умолчанию `jp_to_ru`.

## Размер и обновления

- Стартовый бандл: common-only словарь (~18.5k статей) — компромисс между офлайном и размером.
- Полный словарь (~69k статей) — отдельный пак позже.
- Обновление: новый `dictionary-ja.db` с версией/датой/checksum; замена файла при обновлении приложения или явная загрузка.
- Без бэкенда: статический хостинг/GitHub Releases достаточно.
- При обновлении не терять карточки: они хранят снимки, а не только ссылку.

## Риски

| Риск | mitigation |
|---|---|
| В русской редакции нет нужного слова | fallback на английскую редакцию/ручной перевод; проверить покрытие N5 |
| Русские глоссы неточные | показывать несколько значений, позже — пометки/правки |
| Большой размер БД | common-only, FTS-индексы, измерение размера |
| Лицензия | экран «Источники», текст лицензии, обновление |
| FTS5/trigram недоступны в сборке | проверить при старте; fallback на LIKE |
| Дубликаты карточек | уникальные индексы + UI-состояние |

## Критерии приёмки

- Поиск работает без сети.
- Русский и японский запросы дают результаты.
- Статья отображается без сырого JSON.
- Из текста можно открыть статью.
- Добавление в колоду создаёт одну карточку и не дублирует её.
- Экран «Источники» содержит EDRDG/JMdict и лицензию.
- `dictionary-ja.db` не изменяется приложением.
